# Day 14 — Networking (2)

## Find the interface of a node

Run on the node itself (`ssh node01` for a worker): `ip a` only shows the interfaces of the local machine.

```bash
k get nodes -o wide                              # INTERNAL-IP column
k describe nodes controlplane | grep -i ip       # alternative (also matches unrelated annotations)
ip a | grep -B2 10.244.70.222                    # -B2: also prints the 2 lines above -> interface name + MAC (link/ether)

ip neigh                                         # ARP table: IP, MAC and local interface of the neighbours
ip route show default                            # default gateway
```

How to read an `ip a` output:

| Interface | Kernel type | Role |
|---|---|---|
| **`eth0`** | NIC | **node interface**, carries the INTERNAL-IP |
| `cni0` | bridge | virtual switch of the node's pods, its IP = the pods' gateway |
| `veth…@if3` | veth | host side of a pod's cable (`master cni0`) |
| `flannel.1` | vxlan | pod traffic to the other nodes (overlay) |

```bash
ip -d link show cni0                             # -d (details): the "bridge …" line gives the type
ip link show type bridge                         # all the bridges of the node
bridge link                                      # ports plugged into the bridges (the veth… "master cni0")
```

> KodeKloud lab pitfall: the nodes are pods of another cluster → node IPs are `10.244.x.x/32` (looks like a pod IP: always compare with INTERNAL-IP) and all traffic goes through a fake gateway (`169.254.1.1`) → node01's MAC never shows in the controlplane ARP table, only on node01.

## Ports and connections

```bash
ss -plnt | grep kube-scheduler                   # grep loses the header
ss -plnt | grep -E 'State|kube-scheduler'        # keep it: also match a word of the header
ss -plnt | awk 'NR==1 || /kube-scheduler/'       # line 1 (header) OR the matching lines
ss -plnt | awk '/kube-scheduler/ {print $4}'     # only the 4th column (Local Address:Port)

netstat -anp                                     # -a all sockets (listening + established) · -n numeric (no name resolution) · -p PID/program -> use with grep
netstat -anp | grep etcd | grep 2379 | wc -l     # number of client connections on etcd
```

## CNI

Besides creating the container, the container runtime is responsible for connecting it to the network: it delegates this to a CNI plugin, which links the container to the other containers.

| Path | Content |
|---|---|
| `/opt/cni/bin` | Where to find the binary of the plugin |
| `/etc/cni/net.d` | Where the config of the plugin lives: first file in alphabetical order is used, `type` = the binary executed |
| `/run/flannel/subnet.env` | Flannel: pod IP range (network + subnet of this node) |

### What happens at each container creation

- The **container runtime** (containerd) creates the network namespace, then runs the **CNI plugin** binary with `ADD` (and `DEL` on deletion).
- The plugin wires the container to the node network — same steps as the manual bridge lab:

| Step | Equivalent command |
|---|---|
| 1. Create a veth pair | `ip link add veth-x type veth peer name veth-x-br` |
| 2. One end in the container, the other on the bridge `cni0` | `ip link set veth-x netns <ns>` · `ip link set veth-x-br master cni0` |
| 3. Assign an IP (picked by the IPAM plugin, e.g. `host-local`) | `ip -n <ns> addr add <ip>/24 dev veth-x` |
| 4. Default route via the bridge | `ip -n <ns> route add default via <cni0-ip>` |
| 5. Bring both ends up | `ip -n <ns> link set veth-x up` · `ip link set veth-x-br up` |

- Contract: env vars (`CNI_COMMAND`, `CNI_CONTAINERID`, `CNI_NETNS`, `CNI_IFNAME`) + JSON config on **stdin** → JSON result (IP, routes) on **stdout**.
- **Same node**: pods talk through `cni0`. **Across nodes**: the network plugin adds an overlay or routes (Flannel = VXLAN via `flannel.1`, Calico = BGP/IPIP) → every pod reaches every pod without NAT.

## Kubelet config

```bash
ps aux | grep kubelet                            # --config=/var/lib/kubelet/config.yaml (don't guess the path, ask the process)
```

| File | Content |
|---|---|
| `/var/lib/kubelet/config.yaml` | main config, generated by kubeadm |
| `/var/lib/kubelet/kubeadm-flags.env` | extra flags (e.g. `--container-runtime-endpoint`) |
| `/etc/kubernetes/kubelet.conf` | kubeconfig of the kubelet |

Root directories and K8s paths: see [`cka_cheatsheet_linux_fs.md`](cka_cheatsheet_linux_fs.md).
